# Example mission recordings

These are genuine indexed MCAP recordings generated by the shared First Contact mission runner. Each contains a deterministic **20 m, 20 s kinematic rehearsal at 1 m/s**, using the same `createExamplePoints` reference-sphere geometry available in the application.

## Contents and limits

All recordings identify robot `rover-1`, profile revision `1.0.0`, model `kinematic-point-rover`, and the precise mission source/geometry identity. The simulation clock starts at the fixed replay epoch `2026-11-14T12:00:00.000Z`. Seed `42` is recorded as `unused-deterministic`: this engine has no random noise model.

The files include the declarative command plan, initial/final synthetic state observations, source-space robot states, Foxglove poses and frame transforms, a portable geometric rover proxy, terminal result, and embedded mission/plan JSON attachments. The `mission_local` frame starts at the rover origin with X forward, Y left, and Z up; a recorded transform maps it back to the native body-fixed source frame.

These are workflow and replay examples. They do not contain terrain meshes, imagery pixels, image-sensor observations, collision/contact dynamics, or trained policies. Planet imagery provenance describes the application's reference sphere; it does not turn that sphere into a terrain elevation model. The `physicsValidated`, `terrainContactValidated`, `imageSensors`, and `trainingRun` flags remain false.

## Inspect or replay

Open a file in Foxglove and use its 3D panel with `mission_local` as the display frame. The recording exposes `/tf`, `/robots/rover-1/pose`, and `/scene/robot` for the frame tree, pose trace, and geometric rover. Custom state, command, observation, and result topics can be inspected alongside them. The complete topic list is available from the embedded MCAP channel index.

The records use official `foxglove.PoseInFrame`, `foxglove.FrameTransforms`, and `foxglove.SceneUpdate` JSON schemas. Their binary structure, indexes, timestamps, embedded schemas, source/local transforms, and checksums have been verified by both the TypeScript MCAP reader and an independent Python reader. Foxglove GUI playback has not been exercised in the hosted environment.

## Reproduce and verify

From the repository root, after `npm ci`:

```bash
node scripts/create_mcap_fixture.ts examples/recordings/first-contact-mars.mcap mars
node scripts/create_mcap_fixture.ts examples/recordings/first-contact-moon.mcap moon
node scripts/create_mcap_fixture.ts examples/recordings/first-contact-earth.mcap earth
```

For an independent check, use an isolated Python environment with `mcap==1.6.0` and `jsonschema==4.26.0`, then run:

```bash
python scripts/verify_mcap.py examples/recordings/first-contact-mars.mcap
python scripts/verify_mcap.py examples/recordings/first-contact-moon.mcap
python scripts/verify_mcap.py examples/recordings/first-contact-earth.mcap
```

The Python checker validates every message against its embedded schema, checks the indexed message counts and per-channel sequences, reconstructs native positions from the local-frame transform, and makes a separate linear pass to verify the full MCAP data-section checksum.
